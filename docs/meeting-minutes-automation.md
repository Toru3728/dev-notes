# 議事録作成の自動化

会議の録音から Word 議事録までを、手作業を最小にして回すための手順書。
最終成果物は **A4 の Word ファイル（.docx）** を想定している。

全体の流れはこの 4 ステップだけ。

```
① 録音する  →  ② 文字起こしする  →  ③ Claude で議事録に整形  →  ④ Word で仕上げる
  (会議中)      (会議後 5〜15分)        (2〜3分)                  (1分)
```

慣れると、1 時間の会議が **10〜20 分で配布できる議事録**になる。

---

## 0. 始める前に（介護・福祉の会議では特に大事）

- **録音の同意を取る。** 会議の冒頭で「記録のために録音します」と一言。オンライン会議は録画開始時に通知が出るが、それでも口頭で言う。
- **要配慮個人情報が混ざる前提で考える。** 利用者名・病名・家族の事情などが出る会議なら、クラウドの文字起こしサービスに上げない。→ 後述のローカル Whisper を使う。
- **固有名詞は仮名化する。** 議事録に落とす段階で「A 様」「B 事業所」に置き換える。Claude に整形させるときにルールとして指示できる。
- **録音データの置き場と消し方を決めておく。** 議事録が確定したら音声は削除、が基本。残すなら保管期限を決める。

---

## 1. 録音する

### 方法の選び方

| 方法 | 費用 | 向いている場面 | 注意点 |
|---|---|---|---|
| スマホのボイスメモ | 無料 | 対面の少人数会議・訪問先 | 机に直置きすると振動音を拾う。ハンカチ 1 枚敷く |
| IC レコーダー | 数千円〜 | 長時間・大人数の会議室 | 事前に充電と空き容量の確認。録れていない事故が一番多い |
| Zoom / Teams / Google Meet のクラウド録画 | 契約に含まれることが多い | オンライン会議 | 自動文字起こしが付くならステップ②を丸ごと省略できる |
| PC マイク + リアルタイム文字起こしアプリ | 無料〜 | ハイブリッド会議 | PC のファンの音を拾いやすい |

**迷ったら「対面＝スマホのボイスメモ」「オンライン＝会議ツールの録画」でよい。**

### 録音のコツ（ここで精度の 8 割が決まる）

- マイクは話者から **1m 以内**、テーブルの中央に置く。エアコンの吹き出し口の下は避ける。
- **冒頭に日付・会議名・参加者を声に出して吹き込む。** 「2026 年 8 月 26 日、○○事業所 サービス担当者会議、出席は…」。これだけで議事録のヘッダが自動で埋まる。
- **発言の前に名前を言うルール**にすると、話者分離の精度が上がる。難しければ司会が「では田中さん」と振るだけでもいい。
- ホワイトボードや配布資料は**写真を撮っておく**。音声に残らない情報は後から復元できない。
- 会議が終わったらその場でファイル名を `YYYY-MM-DD_会議名.m4a` に変える。後回しにすると必ず分からなくなる。

---

## 2. 文字起こしする

| ツール | 置き場 | 向き | ひとこと |
|---|---|---|---|
| Notta / Vrew などのクラウド文字起こし | クラウド | 手軽さ重視 | 話者分離が付く。**個人情報を含む会議には使わない** |
| Whisper（ローカル実行） | 自分の PC | 安全性重視 | ネットに出ないので利用者情報を含む会議でも使える |
| 会議ツールの自動文字起こし | クラウド | オンライン会議 | 追加作業ゼロ。精度はツール次第 |

### ローカル Whisper の使い方（安全ルート）

Python が入っていれば `faster-whisper` が速くて扱いやすい。初回だけモデルのダウンロードが走る。

```bash
pip install faster-whisper

# 文字起こし（medium で実用十分、精度優先なら large-v3）
faster-whisper 2026-08-26_担当者会議.m4a \
  --language ja \
  --model medium \
  --output_format txt
```

出てきた `.txt` がステップ③の入力になる。**この時点では誤変換だらけでよい。**直すのは Claude の仕事。

---

## 3. Claude で議事録に整形する

文字起こしテキストを貼り付けるか、ファイルで渡して、こう頼む。

```
添付の文字起こしから議事録を作ってください。

【会議情報】
- 会議名：○○事業所 サービス担当者会議
- 日時：2026-08-26 14:00〜15:00
- 場所：○○事業所 会議室
- 出席者：（分かる範囲で。文字起こしから拾えるならお任せ）

【ルール】
- 文字起こしに無いことは書かない。推測で補わない
- 聞き取れていない・意味が取れない箇所は ［要確認］ と明示する
- 利用者名は「A様」「B様」に置き換える
- 決定事項と ToDo は必ず分けて、ToDo は「担当者・期限」を明記する
- 雑談・脱線は落とす。ただし決定に影響した発言は残す

【構成】
1. 会議情報（日時・場所・出席者）
2. 議題
3. 議論の要旨（議題ごとに 3〜5 行）
4. 決定事項（箇条書き）
5. ToDo（表：内容 / 担当 / 期限）
6. 次回予定
7. ［要確認］一覧
```

**ポイントは「創作させないこと」。**聞き取れなかった箇所を Claude がそれらしく埋めてしまうのが一番危ない。`［要確認］` を必ず付けさせて、人が音声に戻って確認する。

---

## 4. Word ファイルで仕上げる

整形結果を確認したら、続けてこう頼む。

```
これを Word ファイル（.docx）にしてください。
- A4 縦・游ゴシック・本文 10.5pt
- 決定事項と ToDo は表組み
- ヘッダに会議名、フッタにページ番号
- ファイル名：議事録_YYYY-MM-DD_会議名.docx
```

Claude は Word 作成用のスキルを持っているので、見出し・表・ページ番号まで入った .docx がそのまま出てくる。

### 保存とファイル名の決め事

- ファイル名：`議事録_YYYY-MM-DD_会議名.docx`
- 同じ日に同じ会議が 2 回あれば末尾に `_2`
- ローカルと Google ドライブの両方に、同じ内容・同じファイル名で置く

### 配布前に人が見るところ（ここは自動化しない）

- [ ] 日付・会議名・出席者が合っているか
- [ ] `［要確認］` が残っていないか（残っていれば音声に戻って確認）
- [ ] 決定事項が「決まったこと」だけになっているか（検討中のものが混ざりやすい）
- [ ] ToDo に担当と期限が全部入っているか
- [ ] 利用者名・個人情報が残っていないか

**最後の目視は必ず入れる。**議事録は「言った / 言わない」の証拠になる文書なので、AI の出力をノーチェックで配ってはいけない。

## つまずきポイント

| 症状 | 原因 | 対処 |
|---|---|---|
| 文字起こしが崩壊している | マイクが遠い・複数人が同時に話している | 録音位置を見直す。司会が発言を交通整理する |
| 専門用語が全部誤変換 | 辞書に無い介護用語（担当者会議、モニタリング等） | 誤変換のままで OK。Claude への指示に「介護分野の会議です」と足すと直る |
| 決定事項が薄い | 会議で決め切っていない | 議事録の問題ではない。会議の最後に「では決まったことを確認します」を入れる |
| 出席者が拾えない | 冒頭の吹き込みを忘れた | ステップ①の「冒頭に吹き込む」を徹底する |
| 毎回プロンプトを書くのが面倒 | — | ステップ③④のプロンプトを定型文として保存しておく。頻度が上がったらカスタムコマンド化を検討 |

---

## 所要時間の目安（1 時間の会議）

| ステップ | 時間 |
|---|---|
| ① 録音 | 会議時間と同じ（追加作業ゼロ） |
| ② 文字起こし | 5〜15 分（ほぼ待つだけ） |
| ③ Claude で整形 | 2〜3 分 |
| ④ Word 化 | 1 分 |
| 目視チェック | 5〜10 分 |

手打ちで 60〜90 分かかっていた作業が、**実作業 10 分前後**になる。
