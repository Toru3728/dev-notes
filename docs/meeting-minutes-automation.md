# 議事録作成の自動化

会議の録音から Word 議事録までを、手作業を最小にして回すための手順書。
最終成果物は **A4 の Word ファイル（.docx）** を想定している。

全体の流れはこの 4 ステップだけ。

```
① 録音する  →  ② 文字起こしする  →  ③ Claude で議事録に整形  →  ④ Word で仕上げる
  (会議中)      (会議後 5〜15分)        (2〜3分)                  (1分)

事業所ごとに様式が違う場合は、初回だけ ⑤ お手本を写真で撮ってプロファイルを作る
```

慣れると、1 時間の会議が **10〜20 分で配布できる議事録**になる。

---

## 0. 始める前に（介護・福祉の会議では特に大事）

- **録音の同意を取る。** 会議の冒頭で「記録のために録音します」と一言。オンライン会議は録画開始時に通知が出るが、それでも口頭で言う。
- **要配慮個人情報が混ざる前提で考える。** 利用者名・病名・家族の事情などが出る会議なら、クラウドの文字起こしサービスに上げない。→ 後述のローカル Whisper を使う。
- **固有名詞は仮名化する。** 議事録に落とす段階で「A 様」「B 事業所」に置き換える。Claude に整形させるときにルールとして指示できる。
- **録音データの置き場と消し方を決めておく。** 議事録が確定したら音声は削除、が基本。残すなら保管期限を決める。

---

## 1. 録音する

### 方法の選び方

| 方法 | 費用 | 向いている場面 | 注意点 |
|---|---|---|---|
| スマホのボイスメモ | 無料 | 対面の少人数会議・訪問先 | 机に直置きすると振動音を拾う。ハンカチ 1 枚敷く |
| IC レコーダー | 数千円〜 | 長時間・大人数の会議室 | 事前に充電と空き容量の確認。録れていない事故が一番多い |
| Zoom / Teams / Google Meet のクラウド録画 | 契約に含まれることが多い | オンライン会議 | 自動文字起こしが付くならステップ②を丸ごと省略できる |
| PC マイク + リアルタイム文字起こしアプリ | 無料〜 | ハイブリッド会議 | PC のファンの音を拾いやすい |

**迷ったら「対面＝スマホのボイスメモ」「オンライン＝会議ツールの録画」でよい。**

### 録音のコツ（ここで精度の 8 割が決まる）

- マイクは話者から **1m 以内**、テーブルの中央に置く。エアコンの吹き出し口の下は避ける。
- **冒頭に日付・会議名・参加者を声に出して吹き込む。** 「2026 年 8 月 26 日、○○事業所 サービス担当者会議、出席は…」。これだけで議事録のヘッダが自動で埋まる。
- **発言の前に名前を言うルール**にすると、話者分離の精度が上がる。難しければ司会が「では田中さん」と振るだけでもいい。
- ホワイトボードや配布資料は**写真を撮っておく**。音声に残らない情報は後から復元できない。
- 会議が終わったらその場でファイル名を `YYYY-MM-DD_会議名.m4a` に変える。後回しにすると必ず分からなくなる。

## 2. 文字起こしする

| ツール | 置き場 | 向き | ひとこと |
|---|---|---|---|
| Notta / Vrew などのクラウド文字起こし | クラウド | 手軽さ重視 | 話者分離が付く。**個人情報を含む会議には使わない** |
| Whisper（ローカル実行） | 自分の PC | 安全性重視 | ネットに出ないので利用者情報を含む会議でも使える |
| 会議ツールの自動文字起こし | クラウド | オンライン会議 | 追加作業ゼロ。精度はツール次第 |

### ローカル Whisper の使い方（安全ルート）

Python が入っていれば `faster-whisper` が速くて扱いやすい。初回だけモデルのダウンロードが走る。

```bash
pip install faster-whisper

# 文字起こし（medium で実用十分、精度優先なら large-v3）
faster-whisper 2026-08-26_担当者会議.m4a \
  --language ja \
  --model medium \
  --output_format txt
```

出てきた `.txt` がステップ③の入力になる。**この時点では誤変換だらけでよい。**直すのは Claude の仕事。

## 3. Claude で議事録に整形する

文字起こしテキストを貼り付けるか、ファイルで渡して、こう頼む。

```
添付の文字起こしから議事録を作ってください。

【会議情報】
- 会議名：○○事業所 サービス担当者会議
- 日時：2026-08-26 14:00〜15:00
- 場所：○○事業所 会議室
- 出席者：（分かる範囲で。文字起こしから拾えるならお任せ）

【ルール】
- 文字起こしに無いことは書かない。推測で補わない
- 聞き取れていない・意味が取れない箇所は ［要確認］ と明示する
- 利用者名は「A様」「B様」に置き換える
- 決定事項と ToDo は必ず分けて、ToDo は「担当者・期限」を明記する
- 雑談・脱線は落とす。ただし決定に影響した発言は残す

【構成】
1. 会議情報（日時・場所・出席者）
2. 議題
3. 議論の要旨（議題ごとに 3〜5 行）
4. 決定事項（箇条書き）
5. ToDo（表：内容 / 担当 / 期限）
6. 次回予定
7. ［要確認］一覧
```

**ポイントは「創作させないこと」。**聞き取れなかった箇所を Claude がそれらしく埋めてしまうのが一番危ない。`［要確認］` を必ず付けさせて、人が音声に戻って確認する。

## 4. Word ファイルで仕上げる

整形結果を確認したら、続けてこう頼む。

```
これを Word ファイル（.docx）にしてください。
- A4 縦・游ゴシック・本文 10.5pt
- 決定事項と ToDo は表組み
- ヘッダに会議名、フッタにページ番号
- ファイル名：議事録_YYYY-MM-DD_会議名.docx
```

Claude は Word 作成用のスキルを持っているので、見出し・表・ページ番号まで入った .docx がそのまま出てくる。

### 空のテンプレートから始めたいとき

このリポジトリに雛形を置いてある。→ [議事録テンプレート（.docx）](../templates/meeting-minutes-template.docx)

A4 縦・游ゴシック 10.5pt、会議情報の表、決定事項と ToDo の表、フッタのページ番号、
末尾の配布前チェック欄まで入っている。`〔…〕` のグレー文字が差し替え箇所。

Claude に「このテンプレートの体裁で」と渡せば、そのまま埋めた .docx が返ってくる。
体裁を変えたいときは [ビルドスクリプト](../templates/build-meeting-minutes-template.js) を直して作り直す。

```bash
npm install docx
node templates/build-meeting-minutes-template.js
```

## 5. 事業所のフォーマットに合わせる（お手本の写真1枚から）

事業所によって様式が違う（Word・Excel・紙の手書き）。毎回合わせ直すのは無理なので、
**初回だけお手本を写真で撮って「書式プロファイル」を1枚起こす**。2回目以降はそれを指定するだけ。

```
初回だけ： お手本を写真で撮る → Claudeが項目を読み取る → プロファイル(JSON)を保存
2回目以降： プロファイルを指定 → その事業所の体裁で出る
```

入口が写真に揃うので、Word だろうと Excel だろうと手書きだろうと同じ手順で済む。

### 初回：お手本を撮る

- 1ページ目（項目名が全部見えるページ）を**真上から**撮る。斜めだと表の列が読めない
- 記入済みのものを撮るなら、**利用者名が写っている部分は付箋で隠すか、白紙の様式を撮る**
- 2ページ以降に項目が続くなら、そのページも撮る
- Excel の様式なら、印刷プレビューの画面キャプチャでもいい

### 初回：プロファイルを起こす

写真を渡してこう頼む。

```
この議事録の様式に合わせた書式プロファイルを作ってください。
templates/profiles/default.json と同じ構造の JSON で、
company/secretary/minutes/formats/〔事業所名〕.json に保存してください。

- 項目名と並びは写真のとおりに写す（言い換えない）
- 写真に書かれている記入内容は転記しない。項目の枠組みだけ
- improvements は 3 つ全部 true のままにする
```

**中身は転記しない**のが大事。プロファイルに要配慮個人情報が入ると、以後ずっと持ち回ることになる。

### 2回目以降：使う

```bash
node templates/build-meeting-minutes-template.js company/secretary/minutes/formats/〇〇事業所.json
```

空のテンプレートが `templates/built/` に出る。議事録そのものを作るときは、
Claude にプロファイルと文字起こしの両方を渡せば、その体裁で埋まった .docx が返ってくる。

### 「項目は合わせる・改善点は残す」の線引き

お手本に寄せるのは**項目名・並び・表の列・用紙の体裁**まで。
そのうえで、お手本に無くても `improvements` で次の3つを足す。

| 足すもの | 理由 |
|---|---|
| ToDo 表の「担当」「期限」列 | 誰がいつまでにが抜けた ToDo は、あとで必ず揉める |
| ［要確認］一覧 | 聞き取れなかった箇所の置き場。ここが空になって初めて配布できる |
| 配布前チェック欄 | 個人情報の残りを最後に必ず見る。配布時に削除する前提 |

お手本の様式に「担当」欄が既にあれば重複はしない（同名の列があれば足さない）。
足したくないときは、プロファイルの `improvements` を `false` にする。

### プロファイルの中身

`templates/profiles/default.json` が標準の体裁、
[`sample-office.json`](../templates/profiles/sample-office.json) が写真から起こした見本（架空の事業所）。

| キー | 意味 |
|---|---|
| `page.orientation` | `portrait` / `landscape` |
| `page.marginMm` | 余白（mm）。四辺共通 |
| `font.name` / `font.sizePt` | 本文フォントと文字サイズ |
| `headingColor` | 見出しの色（16進6桁）。お手本が黒なら `000000` |
| `title` | 1行目の表題。お手本の呼び方をそのまま |
| `headerText` | ページ上部の見出し。空文字ならヘッダなし |
| `infoFields` | 会議情報の表。`label` と `placeholder` の配列 |
| `sections[].heading` | 節の見出し。**お手本の項目名をそのまま** |
| `sections[].type` | `text`（自由記述）／ `table`（表） |
| `sections[].role` | `decisions` / `todo` / `needs-check`。improvements がどの節に効くかの目印 |
| `sections[].columns` | 表の列。`width`（DXA 固定）か `weight`（比率）で指定 |
| `sections[].rows` | 空の記入行の数 |
| `improvements` | 上の表の3つを足すかどうか |

列幅は `weight` で書いておけば、余白や用紙向きが変わっても合計が本文幅にそろう。
`width` で DXA を直接指定すると、お手本の列幅を再現できる。

### 実在の事業所のプロファイルの置き場

**`company/secretary/minutes/formats/` に置く。このリポジトリには入れない。**
dev-notes は公開リポジトリなので、事業所名が入るものは `company/`（`.gitignore` 済み）側に置く。
公開側には標準プロファイルと架空のサンプルだけを置いている。

---

### 保存とファイル名の決め事

- ファイル名：`議事録_YYYY-MM-DD_会議名.docx`
- 同じ日に同じ会議が 2 回あれば末尾に `_2`
- ローカルと Google ドライブの両方に、同じ内容・同じファイル名で置く

### 配布前に人が見るところ（ここは自動化しない）

- [ ] 日付・会議名・出席者が合っているか
- [ ] `［要確認］` が残っていないか（残っていれば音声に戻って確認）
- [ ] 決定事項が「決まったこと」だけになっているか（検討中のものが混ざりやすい）
- [ ] ToDo に担当と期限が全部入っているか
- [ ] 利用者名・個人情報が残っていないか

**最後の目視は必ず入れる。**議事録は「言った / 言わない」の証拠になる文書なので、AI の出力をノーチェックで配ってはいけない。

## つまずきポイント

| 症状 | 原因 | 対処 |
|---|---|---|
| 文字起こしが崩壊している | マイクが遠い・複数人が同時に話している | 録音位置を見直す。司会が発言を交通整理する |
| 専門用語が全部誤変換 | 辞書に無い介護用語（担当者会議、モニタリング等） | 誤変換のままで OK。Claude への指示に「介護分野の会議です」と足すと直る |
| 決定事項が薄い | 会議で決め切っていない | 議事録の問題ではない。会議の最後に「では決まったことを確認します」を入れる |
| 出席者が拾えない | 冒頭の吹き込みを忘れた | ステップ①の「冒頭に吹き込む」を徹底する |
| 毎回プロンプトを書くのが面倒 | — | ステップ③④のプロンプトを定型文として保存しておく。頻度が上がったらカスタムコマンド化を検討 |

## 所要時間の目安（1 時間の会議）

| ステップ | 時間 |
|---|---|
| ① 録音 | 会議時間と同じ（追加作業ゼロ） |
| ② 文字起こし | 5〜15 分（ほぼ待つだけ） |
| ③ Claude で整形 | 2〜3 分 |
| ④ Word 化 | 1 分 |
| 目視チェック | 5〜10 分 |

手打ちで 60〜90 分かかっていた作業が、**実作業 10 分前後**になる。
