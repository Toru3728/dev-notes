# 問い合わせ返信の下書き（Reply）

お客様からの問い合わせ文を受け取り、ていねいな返信の下書きを作る。

## 入力
- お客様からの問い合わせ文＝ $ARGUMENTS
- 問い合わせ文が無ければ「お客様の問い合わせ文を貼って」と一言だけ促す

## 出力フォーマット（この流れを厳守）

```
【件名案】<内容が一目で分かる件名>

〇〇様

<お礼：問い合わせへの感謝・あいさつ>

<回答：質問に具体的に答える。複数あれば項目ごとに>

<次のご案内：次のステップを提示（日程調整／資料／無料相談など）>

<締めの挨拶>

となりにAI　とーる
（AI×介護DX 伴走パートナー）
```

### 各パートの作り方
1. **お礼** … 問い合わせてくれたことへの感謝から入る。冒頭で安心感を出す
2. **回答** … 質問に正面から、具体的に答える。複数の質問は分けて答える
3. **次のご案内** … 「次にどうすればいいか」を1つ示す（例: 「30分の無料相談で詳しくお話しできます」）。押し売りにしない
4. **締めの挨拶** … やわらかく締める（「何でもお気軽にどうぞ」等）

## 口調・トーンのルール
- **かたすぎない敬語**（です・ます調。丁寧だけど堅苦しくない、温かみのある言葉づかい）
- とーるさん＝となりにAIのブランド（安心・寄り添い・誠実）に合わせる
- 専門用語はかみ砕く。相手の不安に寄り添う一言を入れてOK
- 過度なへりくだり（「弊社」連発・長すぎる前置き）は避け、読みやすく

## 大事なルール
- **問い合わせ文に書かれていない事実・条件（料金・日程など）を勝手に断定しない**
  - 情報が無くて答えられない点は「確認のうえご連絡します」と誠実に書く
- 宛名が不明なら「〇〇様」、分かれば実名を使う
- 末尾に必要なら「※とーるさん確認ポイント」を1〜3個だけ添える（送信前に埋める箇所）

## 保存
- 下書きを `company/secretary/replies/YYYY-MM-DD_<件名>.md` に保存
- 同日同件名があれば連番（_2 など）
- 保存後「返信の下書き保存したよ → パス」と簡潔に報告

## コミュニケーション
- フランクに。まず下書きを表示してから保存報告する
- これは「下書き」なので、最後に「送信前にチェックしてね」と一言添える
