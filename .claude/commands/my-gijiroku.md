# 議事録作成（Minutes）

打ち合わせのメモを受け取り、**毎回同じフォーマット**の議事録に整える。

## モードの判定（最初にここを見る）

| 条件 | モード | 出力 |
|---|---|---|
| 書式プロファイル（JSON）も様式の写真も渡されていない | **標準モード** | 下の4項目・Markdown |
| 書式プロファイル（JSON）が渡された／`company/secretary/minutes/formats/` のファイルを指定された | **事業所モード** | プロファイルどおりの項目・Word |
| 様式の写真だけが渡された | **プロファイル作成** | まずプロファイルを作って保存する |

**指定が無ければ必ず標準モードで動く。** 迷ったら標準モード。
事業所モードは明示的にプロファイルか写真が来たときだけ。

## 入力
- ユーザーが渡す打ち合わせメモ（雑な箇条書き・走り書きでOK）＝ $ARGUMENTS
- メモが $ARGUMENTS に無い場合は「メモを貼ってください」と一言だけ促す

## 標準モードの出力フォーマット（厳守・この4項目以外は増やさない）

```
# 議事録：<打ち合わせのタイトル／議題>

- **日時**: YYYY-MM-DD（HH:MM〜 / 分かる範囲で）
- **参加者**: 名前をカンマ区切りで

## 決まったこと
- （合意・決定事項を1項目ずつ。誰の意見かは不要、結論だけ）

## 次のアクション
- [ ] <やること>（担当：◯◯／期限：YYYY-MM-DD）
```

## 整え方のルール
1. **日時**: メモに日時があればそれを使う。無ければ今日の日付を入れ、時刻は空欄でよい
2. **参加者**: メモから拾う。役職・敬称はメモに合わせる。不明なら「（記載なし）」
3. **決まったこと**: 「決定・合意・方針が固まったこと」だけを抽出。検討中・未決のものは入れない
4. **次のアクション**: 「誰が・何を・いつまでに」を可能な範囲で補う。担当/期限が不明なら「担当：未定」「期限：未定」と明記（空にしない）
5. 雑なメモでも上記4項目に振り分けて構造化する。**勝手に事実を創作しない**（メモに無い決定事項は足さない）
6. メモに「保留」「次回」「TODO」等があれば → 次のアクション側に寄せる

## 事業所モード（プロファイルが渡されたとき）

事業所ごとに議事録の様式が違うので、**お手本から起こした書式プロファイル**に合わせて出す。
仕組みの全体像は `docs/meeting-minutes-automation.md` の「事業所のフォーマットに合わせる」を参照。

1. プロファイルの `title` / `infoFields` / `sections` を**そのまま**使う
   - 項目名は言い換えない。「検討内容」なら「議論の要旨」に直さない
   - 節の並びもプロファイルの順どおり
2. `improvements` が true のものは、お手本に無くても足す
   - `todoOwnerDeadline` … ToDo 表に「担当」「期限」列（同名の列が既にあれば足さない）
   - `needsCheckSection` … ［要確認］一覧を末尾に
   - `preDistributionChecklist` … 配布前チェック欄（配布時に削除する前提）
3. **標準モードの4項目（決まったこと／次のアクション）を持ち込まない。** 項目はプロファイル側が正
4. Word で出す（docx スキルを使う）。空のテンプレートが欲しいだけなら
   `node templates/build-meeting-minutes-template.js <プロファイル.json>`
5. 利用者名は「A様」「B様」に仮名化する。メモに実名があっても議事録には残さない

## プロファイル作成（様式の写真が渡されたとき）

1. 写真から**項目名・並び・表の列**を読み取る
2. `templates/profiles/default.json` と同じ構造の JSON にする
3. **写真に書かれている記入内容は転記しない。** 項目の枠組みだけを写す
   （プロファイルに要配慮個人情報が入ると以後ずっと持ち回ることになる）
4. `improvements` は 3 つ全部 true にする
5. `company/secretary/minutes/formats/<事業所名>.json` に保存する
   - **dev-notes は公開リポジトリなので `templates/profiles/` には置かない**
6. 読み取れなかった項目は `〔要確認〕` を placeholder に入れて、最後に何が読めなかったか報告する

## 保存
- 整えた議事録を `company/secretary/minutes/YYYY-MM-DD_<タイトル>.md` に保存する
  - ファイル名のタイトルは短く（例: `2026-06-10_A社AI研修.md`）
  - 同日同タイトルが既にあれば連番（_2 など）を付ける
- 事業所モードのときは .docx を `company/secretary/minutes/YYYY-MM-DD_<タイトル>.docx` に保存する
  （Markdown は作らなくてよい。配布するのは Word の方）
- 保存後に「議事録を保存したよ → パス」と簡潔に報告する

## コミュニケーション
- フランクに。整えた結果（議事録本文）を表示してから保存報告する
- 決まったこと/次のアクションが0件なら、その項目は「（なし）」と書く（項目自体は消さない）
- メモから読み取れず迷う箇所があれば、議事録の末尾に「※確認したい点」として1〜3個だけ添える
