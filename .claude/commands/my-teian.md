# 提案書下書き作成（Teian）

初回訪問のヒヤリング内容を受け取り、事業所向けの提案書の下書きを作る。
ディスパッチ（外出先のスマホから一行＋写真）で動かせるよう、入力は雑でOK。

## 入力
- ヒヤリング内容＝ $ARGUMENTS（次のどれでもOK）
  - 手書きヒヤリングシートの**写真**（画像ファイルパス）→ Readで読み取る
  - テキストのメモ（雑な箇条書き・音声入力の文章でOK）
- 入力が無ければ「ヒヤリングシートの写真かメモをちょうだい」と一言だけ促す
- 写真で読み取れない字は勝手に補完せず［判読不能・要確認］と書く

## 手順
1. 入力をヒヤリングシートの構成（①訪問情報〜⑧次のアクション）に沿って整理する
2. **④「いま一番困っていること」の現場の生の言葉**を特定する ← 提案書の軸
3. 下記フォーマットで下書きを生成する
4. `company/consulting/proposals/YYYY-MM-DD_<事業所名>.md` に保存する
   - 同日同名があれば連番（_2 など）

## 出力フォーマット（提案書の型）

```
# ご提案書（下書き）：<事業所名> 様

- **作成日**: YYYY-MM-DD
- **宛先**: <対応者名>様（<役職>）
- **提案者**: となりにAI とーる（AI×介護DX 伴走パートナー）

## 1. お伺いした現状・困りごと
（④の生の言葉を「」でそのまま引用して書き出す。言い換えない。
 ②③の事実＝規模・記録方式・ICT環境を2〜3行で添える）

## 2. ご提案
（一番の困りごとに対応する具体策を1〜2個。スモールスタート前提。
 現在のICT環境③で無理なく始められるものにする）

## 3. 期待できる効果
（時間・負担・職員さんの安心の3観点から。数字を出す場合は必ず「目安」と明記）

## 4. 費用と補助金
（概算＋活用できそうな補助金：ICT導入支援事業／IT導入補助金 等。
 金額・補助率はすべて［要確認］タグ付き）

## 5. 進め方（スモールスタート）
（ステップ1〜3。最初の一歩は「体験会」「1フロアだけ」など小さく。
 ⑧で約束した期日があれば最初のステップに反映する）
```

## 大事なルール
- **ヒヤリングに無い事実を創作しない**。推測・仮置きの箇所はすべて［要確認］タグを付ける
- 提案は**「一番の困りごと」1つに絞って深く**。全部盛りの総花提案にしない
- 「人を置いていかないDX」のトーン：職員さんの不安への配慮（研修・並走サポート等）を必ず1箇所入れる
- ⑤に「ICT導入を途中でやめた経験」があれば、**その理由を避ける設計**を「2. ご提案」か「5. 進め方」に反映する
- 専門用語はかみ砕く。介護現場の人がそのまま読める言葉で書く

## 保存・報告
- 保存後「提案書の下書き保存したよ → パス」と簡潔に報告
- 末尾に「※とーるさん確認ポイント」を1〜3個添える（金額・固有名詞など、送る前に埋める箇所）
- これは「下書き」なので、最後に「事業所に出す前にチェックしてね」と一言添える

## コミュニケーション
- フランクに。まず下書き本文を表示してから保存報告する
- ディスパッチ経由（ユーザーが外出中）でも、帰宅後に読めば分かる報告を残す
