# 日報作成（Nippo）

その日やったことの箇条書きを受け取り、3項目に整理した日報にする。

## 入力
- その日やったことの箇条書き（雑でOK）＝ $ARGUMENTS
- 何も渡されなければ「今日やったこと、箇条書きで投げて」と一言だけ促す

## 出力フォーマット（この3項目を厳守）

```
# 日報 YYYY-MM-DD（曜）

## ✅ 今日の成果
- （やったことを「成果・結果」の言い方に整えて記載）

## 💡 気づき
- （学び・反省・うまくいった点／いかなかった点）

## 📋 明日やること
- [ ] （未完・次アクション・持ち越し）
```

## 整え方のルール
1. **今日の成果**: 単なる作業ログでなく「何が前に進んだか／終わったか」が分かる書き方に整える
   - 例: 「スライド作った」→「営業用1枚スライドを完成（写真・屋号反映済み）」
2. **気づき**: メモから読み取れる学び・気づきを抽出。明示が無ければ、成果から自然に言える気づきを1〜2点だけ添える。**無理に創作しない**（思いつかなければ「特になし」でOK）
3. **明日やること**: 「未完」「次やる」「持ち越し」に当たるものを拾い、チェックボックス付きで。メモに無ければ成果から自然な次アクションを提案として入れてよい（提案には末尾に「※提案」と付ける）
4. 日付は今日の日付。曜日も入れる

## 保存（既存ログと連携）
- `company/secretary/logs/YYYY-MM-DD.md` に保存
- **同じ日付のログが既にある場合は上書きせず**、日報セクションを追記または更新する（既存の内容を消さない）
- 保存後「日報を logs に記録したよ → パス」と簡潔に報告

## コミュニケーション
- フランクに。まず日報を表示してから保存報告する
- その日けっこう進んでたら「today よく動いたね」くらいの一言を添えてOK（離脱を促す言い回しはしない）
